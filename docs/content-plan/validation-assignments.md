# Top-20 validation and content assignments

Content Plan → Content assignments can validate the top 20 or **Expand and verify pool** from a completed research run. Expansion selects up to 40 ranked existing-page opportunities and 20 new-page candidates, preserving original ranks and excluding service searches. There is no quota of approved assignments. It consolidates canonical target pages, retaining every original question and its separate source evidence. It does not generate articles, briefs, outlines or a calendar.

Validation reads up to three MedicareFAQ pages per assignment and runs one bounded independent web search through the configured Anthropic account. A separate skeptical AI pass evaluates support, qualifications and overlap. Proposed policy changes can trigger one additional official-source search. An official-rule verdict must cite a supplied government-source passage. Search citations are a limited sample, not measured Google/Bing rankings. The server copies selected passages directly from source text. Source metrics keep their original research dates; validation does not refresh those imports. New-page investigations remain provisional when no target or complete site coverage has been established.

Ready for review means the required checks passed, not that content is approved. Missing pages, unsupported findings, stale supporting evidence or unavailable search results remain Needs research. Existing coverage can yield No change suggested. Keep is available only for Ready for review; all completed assignments can be deferred, rejected or left for review.

Progress saves after each two-assignment batch. Keep the section open until completion, or resume later. A server lease prevents concurrent tabs repeating a batch. Loading completed validation does not call AI again. Retry failed checks creates a new snapshot, retaining successful assessments and retrying only failed checks. Review decisions are versioned and tied to their validation snapshot; they are not automatically carried into a retry.

Only authorized analysts/admins can run checks or save decisions. Verified viewers can inspect results. Completed snapshots are immutable. Keep requires both verification passes in the API and database. The additional guard is in `20261113182418_assignment_second_verification.sql`; existing decisions are not deleted or modified.

Validation history retains earlier snapshots. The latest earlier decision for a matching assignment is displayed with its note. A fingerprint compares topics, source evidence, findings and verification outcomes, ignoring retrieval timestamps; changed evidence prompts a fresh decision. An unchanged Keep is counted only when the current two-pass result is Ready for review. Original records remain accessible even after research refreshes. Expanded runs may reuse unchanged two-pass assessments from the same research within 24 hours. The runner is still user-started and requires the section to remain open; it is not a background scheduler or a source-refresh automation.

Remaining milestones include review of proposed assignments, refreshed evidence collection, scheduling constraints and explicit authorization to generate a calendar. No calendar or publishing automation is enabled here.

## Automated research resolution

Resolve research blockers creates a new validation snapshot from the latest completed run. Only Needs research assignments are processed; successful prior results and review records remain intact. The action is idempotent for resolution-v2. A separate Retry failed checks snapshot can retry technical failures without rerunning completed research.

Resolution selects up to six MedicareFAQ pages from the saved site inventory (prioritizing the exact target and matching plan/part letters), reads fresh bounded excerpts, and performs at most two targeted source-cited searches. A research assessment is followed by an independent reconciliation. One structural repair is allowed for the first assessment using the same evidence. No open-ended agent loop or autonomous publishing is enabled.

Each topic must cite an actual server-supplied passage. Positive coverage can produce No change suggested despite incomplete inventory. A genuine new-page proposal remains provisional. The reviewer can discard an unnecessary improvement when coverage is demonstrated but cannot invent an unreviewed replacement task. Optional editorial checks are separate from blockers. Rule changes need a relevant supplied government passage; carrier claims need relevant carrier/regulator/NAIC/AM Best evidence from explicitly recognized hosts. Host matching alone is not evidence of relevance: the independent review checks scope and qualifications. Conflicts, unsupported changes, stale metrics, duplicate target scopes, and unknown new-page scope stay held.

The review UI exposes blocker filters, exact outstanding questions, matched pages, original proposals and supporting verification quotes. Keep remains a manual decision protected by existing API and database checks. Existing imported metrics retain their dates. No calendar, articles, outlines or briefs are generated. The user-started runner must remain open while batches run, or be resumed later.

Exact-intent checks prevent a generic carrier page from clearing a named-carrier question, cost definitions from clearing calculator intent, and financial ratings alone from clearing reviews intent. Index/category pages cannot be the final coverage evidence. During a rules upgrade, earlier no-change results are retained only after these checks pass; failed matches and unresolved results are re-investigated in a new snapshot. The prior snapshot remains immutable.
